# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
(an app started from it numbers its releases 1, 2, 3; docs/releasing.md).

Each release moves everything under `[Unreleased]` into its own section
(AGENTS.md, "Release flow"); `./tools/release.sh` does it, and
`tests/Unit/ReleaseTest.php` fails until the version in `VERSION` has one.

## [Unreleased]

### Added
- **Email, from the queue** (docs/mail.md). `MailPort` is the one way out; the default adapter is Resend's HTTP API through Guzzle (`ResendMailer`), and another provider, SMTP among them, is a new adapter behind it (docs/mail.md, "Another provider"). A `send-mail` job carries the message and a key the provider drops repeats of, so a job run twice sends once; plain text, from `MAIL_FROM`, links on `APP_URL`. Without `RESEND_API_KEY`, a development machine writes each email to the worker's log and production refuses, so the Queue page shows it. Porting: `src/app/Domain/Mail/`, `src/app/Libraries/Mail/`, `src/app/Libraries/Clients/Resend*.php`, `src/app/Domain/Ports/{Mail,ReceivedMail}Port.php`, `src/config/container/mail.php` and `routes/mail.php`, the `mail` block in `src/config/container.php`, the Compose environment, the migrations `20261107000001`–`20261107000004`, and the tests beside them.
- **A site's form emails whoever may read the Inbox**: every enabled owner and administrator, one email each, `Reply-To` the sender. Porting: `SubmissionNotice`, `UserRepository::addressesWithAnyRole()`, `Reception`'s constructor.
- **Invitations are emailed** (docs/invitations.md): the job holds only the invitation's id; the worker issues the link as it sends and keeps its hash only once the email has gone. **Send again** emails a new link; the app never shows the link. Porting: `InvitationMail`, `InvitationEmail`, `InvitationMailHandler`, `Invitations::issueLink()`/`sendAgain()`, `POST /api/invitations/{id}/send`, `InvitationsView.vue`.
- **Password reset by an emailed link** (docs/password-reset.md): "Forgot your password?" on the sign-in page, the same answer whether or not an address has an account, one use, one hour, the newest link only, three requests an hour per account, and an email when a password is changed. Porting: the `passwords` slice (`PasswordResets`, its repository, controller, routes, container), `IdentityPort::changePassword()`, the two views and their routes.
- **Mail sent to the domain reaches the Inbox** (docs/mail.md, "Mail sent to the domain"): Resend's `email.received` webhook at `/webhooks/resend`, checked by its Svix signature and recorded by its id so a repeat does nothing, queues the message; the worker fetches it, files it as an Email submission (no site; a site may not post that form), and emails whoever may read the Inbox. Needs `RESEND_WEBHOOK_SECRET` and `RESEND_RECEIVING_KEY` (docs/accounts.md). Porting: `Inbound`, `InboundMailHandler`, `WebhookController`, `WebhookDeliveryRepository`, `FormDefinition::$fromSites`, `form:email`.
- **The first admin comes from Doppler, in dev as in prod.** `FIRST_USERNAME` and `FIRST_USER_PASSWORD`, a different pair in each config. `prod`'s makes the first owner on the first deploy, as before; with `dev`'s passed in by name, `UserSeeder` makes that account the local owner and never prints its password (README.md, docs/accounts.md).
- **The server's daily advisory check, designed** (docs/supply-chain.md, "Watching for advisories, on the server"): Caddy, PHP, MariaDB, Composer packages and Debian checked against what is running, reported once per finding, never changed by the check. Not built yet; where it reports is in OPEN-QUESTIONS.md.
- **Sample content for development** (`ContentSeeder`, docs/content.md): a published post, a published page of blocks and a draft post, written through Publishing; refuses to run outside development. README and `tools/setup.sh` seed it with the accounts. Brought back from KAW Meetup.
- **CI** (`.github/workflows/ci.yml`, docs/releasing.md): the gate, `./tools/test.sh --coverage`, on every push to `main` and every pull request; read-only, no secrets, actions pinned to commits (`tests/Unit/CiWorkflowTest.php` holds it to that). Porting: the workflow and its test.
- **The content slice** (docs/content.md), the first part of the content model (docs/content-model.md), built in KAW Meetup and brought back: any record type declared as `record_type:<name>` gets drafts, a publish state machine (draft, published, retired), a revision for every publish that can be restored, and a slug history no other record may reuse. The first record type is `posts`: Markdown bodies with no raw HTML, no top-level heading and only safe links, edited on a plain Posts page. New permissions `content-edit` and `content-publish`, for administrators.
- **Media** (docs/content.md, "Media"): a Media page uploads images (re-encoded by GD to a JPEG of at most 2400 px with nothing of the file but its pixels; one image per picture) and describes them (alt text, caption, licence and credit); pages get image and gallery blocks; a record cannot be published with an undescribed or uncredited image; an image becomes public at `/api/site/media/<id>.jpg` once a published record uses it. Files go through `StoragePort` (local disk until an object-storage adapter is approved). Adds GD to the PHP image and `ImagePort`. Built first in KAW Meetup. Porting: the Dockerfile's GD lines, `ImagePort`/`GdImages`, the media files under `Domain`, `Models`, `Libraries` and `Controllers`, the `20261021000006` migration, and the frontend's `MediaView.vue` and block editor. The Media page says where each image is used, drafts included.
- **Images in a record type's own fields** (docs/content.md, "Media"): `RecordFields::images()` names them (an event's cover, say), and they are checked, made public and given to the site like an image block's. Brought back from KAW Meetup's event covers. **Porting:** every `RecordFields` gains `images()`; return `[]` from any that names none.
- **Pages, whose body is blocks** (docs/content.md, "Blocks"): `BodyFormat` lets a record type keep its body as Markdown or as blocks from a fixed set (heading, text, quote, callout, questions and answers, call to action, table); anything else is refused, naming the block. `pages` is the first block type, with a plain block editor (`BlocksEditor.vue`) and `/api/site/pages`. Images and galleries come with media.
- **The content site API**: `GET /api/site/<type>` (every published record as last published, with old slugs to redirect, times in ISO UTC) and `/api/site/<type>/retired`, public and read-only, as Waffle Site's contract has it.
- **Change notices**: each publish, retire or restore queues a `site-change-notice` naming the record type and the slugs whose pages changed, coalesced for a minute, which the worker sends to the site's repository as a GitHub `repository_dispatch` (`change-notice`); Waffle Site's `rebuild.yml` turns it into a scoped rebuild. Needs `SITE_REPOSITORY` (in `docker-compose.prod.yml`) and `SITE_DISPATCH_TOKEN` (Doppler). Adds Guzzle, from the approved list.

- **Storage** (docs/storage.md): `StoragePort` and `LocalDiskStorage` on a new `storage_data` volume mounted at `/var/www/storage` on php and worker, with `FakeStorage` for tests. Brought back from KAW Meetup's member photos. The volume is not backed up yet (OPEN-QUESTIONS.md).
- **`IdentityPort::setRole()`** gives an account exactly one level, or none. Brought back from KAW Meetup, where a member's level follows their approval.

- **Forms from the site** (docs/forms.md): sites registered on a Sites page (owners), each with a key issued once and kept as a hash, which the site's Caddy sends as `X-Site-Key`; `POST /api/site/forms/<name>` takes JSON or a browser's form post, ignores a filled honeypot, limits each visitor (an address hashed with the day, never stored) to 5 in 10 minutes, and keeps what the form's parser accepts in an Inbox, deleted after `form_retention_days` (180) by `/cron/forms` nightly. The skeleton declares `contact`. New permissions `forms-manage` and `sites-manage`. Porting: `src/app/{Domain,Models,Libraries}/Forms/`, the four controllers, `SiteKeyMiddleware`, `src/config/{container,routes}/forms.php`, the `20261021000005` migration, the `forms.names` gathering in `container.php`, the form-body exception in `CrossSiteRequest`, the crontab line, the two views.
- **Invitations** (docs/invitations.md), the first part of how people join (RESOLVED_QUESTIONS.md): owners invite administrators and users, administrators invite users, by a single-use seven-day link, emailed (below). Accepting sets a name and password and signs the person in at the invited level. Tokens are stored only as their SHA-256. New permission `invitations-manage`, pages Invitations and Join, `IdentityPort::createAccount()`, and the auth store's `refresh()`. Built first in KAW Meetup.

### Security
- **vite 8.3.5 and follow-redirects 1.16.2** in the frontend, for Vite's dev-server advisories (GHSA-9jrq-w75r-8gcw, GHSA-rq7h-c2jc-7f22, GHSA-vfpm-58rq-9qcg, and launch-editor's GHSA-r825-w8mm-5pxw, GHSA-587h-7wmj-h5pm, GHSA-698v-4r3x-3vcv) and GHSA-mrwp-f3q8-3g9p in axios's redirects. None reached production: the dev server is never deployed, and in the browser axios does not use follow-redirects. Porting: `./tools/npm.sh update vite follow-redirects`.
- **symfony/config and symfony/filesystem 8.1.11** (through Phinx), for GHSA-5jff-8h8q-r5qx and GHSA-6prc-h956-hxjq, which stop a project's release build at `composer audit`. Neither is reachable in the skeleton. Let in inside the cooldown on the owner's call, and recorded in `cooldown-exceptions.txt`. Porting: `./tools/composer.sh update symfony/config symfony/filesystem` (with `COMPOSER_COOLDOWN_DAYS=0` until 2026-11-11).
Found by a review of what KAW Meetup built, and fixed there first.
- **A release is trusted only as far as GitHub Actions built it**: the server deploys only files the workflow's bot uploaded, and checks a release kept on disk against the files it was unpacked with; CI runs npm only in containers that see `src/frontend`, the build with no network, and takes only `index.html` and `assets/` from it, with no token left in the checkout; the app's containers mount the release read-only and the worker runs as `www-data`; the alert webhook never goes on a command line and alerts are escaped for Slack; the poller refuses to run as anyone but `deploy`; the install docs pipe the Doppler token in and protect every tag with a ruleset.
- **Forms counted every visitor as the site's server.** The app's Caddy rewrites `X-Forwarded-For` to the site server's address, so all visitors shared one rate-limit bucket and one script could block everyone. The address now comes from `X-Visitor-Address`, which Waffle Site's Caddy writes, read only behind the site key. Porting: `Domain/Forms/Visitor.php`, `SiteFormController`.
- **The visitor hash was keyed by a value in the same database**, so a copy of the database could reverse it; it is now an HMAC whose key is made once and kept in storage (`Reception::KEY`). Porting: `Reception.php`, its container entry.
- **The Markdown check missed HTML** between escaped backticks and in a code span broken by a blank line, and **unsafe links defined inside a quotation or a list**. Porting: `Domain/Content/Markdown.php`. (Waffle Site now also sanitises what it renders.)
- **An administrator could revoke an owner's invitation for another administrator**; revoking follows who may invite whom (403 otherwise). Porting: `Invitations::revoke()`, `InvitationController`.
- **Two people marking one submission at once could both succeed**; it is decided under the row's lock. Porting: `SubmissionRepository::transactional()`, `InboxController`.
- **`/api/%73ite/` was given a session**; `SessionCookie::wantedFor()` decodes the path first.

### Fixed
- **The front Caddy names the app `<slug>-app` on the `edge` network, never the bare slug** (docs/edge.md, failure 11). A droplet named for its slug resolves that name to itself, so while the app was down the front Caddy proxied to itself and answered 308 instead of 502. And `cp` the front Caddy's files into `/opt/edge`, never `install` or `mv`: Docker mounts the Caddyfile itself. Porting: `deploy/edge/Caddyfile`, the alias in `docker-compose.prod.yml`, docs/edge.md, and recreate the front Caddy once.
- **The session cookie is the project's own** (`waffle_session`, which `tools/rename-project.sh` makes `<slug>_session`), not PHP's `PHPSESSID`: two apps run side by side on localhost shared one cookie, since cookies ignore the port, and signed each other out. Signing in again is needed once after the change. Porting: `SessionCookie::NAME` and the `session_name()` line in `src/public/index.php`.
- **A public image must stay described**: blanking its alt text or dropping a credit its licence needs is refused, since the change notice it sends would start a site build that fails (`MediaLibrary::describe()`).
- **Links are https:// in printable ASCII** (`ContentText::optionalHttpsUrl()`, used for credit links): a pasted non-breaking space passed the app's check and failed the site's.
- **A revision holding a field its type has since lost** restores without writing a missing column; `used_by` also counts what the site shows. Found by a review of KAW Meetup's media work. Porting: `ContentText.php`, `MediaDetails.php`, `MediaLibrary.php`, `Publishing.php`, `RecordRepository.php`.
- **A public image's new description reaches the site**: describing an image that published pages show queues a change notice naming each of them (`Publishing::describeImage()`, docs/content.md 28), so a corrected credit no longer waits for an unrelated rebuild. Found in KAW Meetup. Porting: `Publishing.php`, `MediaController.php` and its container entry.
- **A revision published before its type gained a field** reads as having none (null) for it, instead of warning on every site API request and breaking a restore (`RecordRepository`, docs/content.md 27). Found when KAW Meetup's events gained covers. Porting: `RecordRepository.php`.
- **Nothing uploaded was actually stored.** The `storage_data` volume belonged to root while php-fpm runs as `www-data`, and `LocalDiskStorage` took PHP's warnings for success, so a put reported nothing and stored nothing. The PHP image now creates `/var/www/storage` owned by `www-data`, and the adapter fails loudly when it cannot write. Found uploading the first image in KAW Meetup. Porting: `docker/php/Dockerfile`, `LocalDiskStorage.php`; on an existing volume, `docker compose exec php chown www-data:www-data /var/www/storage` once.
- **The first test run in a new project died with exit 137.** `tools/test.sh` waits for the php container's own `composer install`, but checked for "php-fpm" in PID 1's command line, which the startup shell's `... && exec php-fpm` contains from the start; so it never waited, ran a second install beside the first, both broke on the shared download cache, and the container exited. It now checks PID 1's name. Proven on a fresh project: the first run passes. Porting: the `php_ready` function in `tools/test.sh`.
- **A request that needs no session no longer gets one.** Route guards were built while routes were registered, which built Delight\Auth and so started a session, and set its cookie, on every request. Guards are now built only when a guarded route runs (`Libraries/Middleware/Deferred` for `can:<permission>`, class names for the rest), and `src/public/index.php` starts no session for `/api/site/`. Found when the site API set cookies in KAW Meetup. Porting: `Deferred.php`, the `$can` line and `->add(AuthMiddleware::class)` in every route file, `SessionCookie::wantedFor` and its use in `index.php`.
- **Signing out from the browser** failed with 415 and left the session signed in, with the navigation gone: axios labels a POST with no body a form, which the API refuses as a cross-site defence. The API client now declares JSON for every body and sign-out sends `{}`; `FrontendClientTest` holds both, since the suite never drives the browser frontend. Found in KAW Meetup's preview. Porting: `src/frontend/src/api/client.js`, `src/frontend/src/stores/auth.js`, and the new test.
- **Signing in from a browser on a port that is not the default** (`:8080` locally, or any address with a port) was refused as cross-site: Slim builds the request's Host header without the port, so it never matched the browser's `Origin`. The same-site check now compares the origin with the request's own host and port. Found previewing KAW Meetup over Tailscale. Porting: the change is in `SameSiteMiddleware` and `tests/Feature/CrossSiteTest.php`.
- **A project made from Waffle passes its own tests.** Found by the first real project, KAW Meetup: `CreateProjectTest` runs the rename against the framework's own files and placeholders, which a project no longer has, so the rename now removes it (failure 19 in docs/create-project.md); `ReleaseTest` wrote the framework's repository name escaped, where the rename changed it, and now writes it plainly; a test forbids escaped placeholders. Proven on a fresh project: its whole gate passes. Porting: delete `tests/Unit/CreateProjectTest.php` and its line in `tests/Pest.php`.

- **The rename keeps the companions' names.** It renamed every "Waffle", so a project's documents talked of "KAW Meetup Site" and "KAW Meetup Iron", which do not exist. `Waffle Site`, `Waffle Iron`, `waffle-site`, `waffle-iron` and `waffle-api.md` now stay as they are (failure 20 in docs/create-project.md). Found in KAW Meetup. Porting: nothing to port into code; in a project already renamed, put those names back by hand where its documents mean the companion projects.

### Changed
- **PHP 8.5.12 at least.** The image is built from the exact `php:8.5.12-fpm` rather than `php:8.5-fpm`, and the build refuses an older PHP; composer.json requires `^8.5.12`, so CI's composer install does too. `tests/Unit/PhpVersionTest.php` holds all of these to the floor. Porting: those files and `composer.lock` (`./tools/composer.sh update --lock`); an existing machine needs `docker compose build php worker` once.
- **Deploys are pulled by the server; rsync is removed in favour of polling** (docs/pull-based-deployments.md). The workflow no longer reaches the server: it builds the release and attaches `waffle-N.tar.gz` and its `.sha256` to the GitHub release, with no secrets. The server checks GitHub every minute (`deploy/pull.sh`, installed as `waffle-pull`, run by `deploy/systemd/waffle-deploy.timer`, whose `REPO` and `DEPLOY_AUTHORS` each project fills in), refuses anything older than live, from an unapproved publisher or failing its checksum, unpacks it into `/opt/waffle/releases/N` and runs its own `deploy/deploy.sh`, which migrates with the previous release still serving, switches `current`, checks `/cron/health` and HTTPS, and switches back if either fails. A rollback (`waffle-pull deploy 7`) holds until a newer release is published, and a deploy replaces only the app's own block of the crontab, which it shares with a site on the same server. Doppler has one config, `prod` (was `prod-serve`); `prod-deploy`, the GitHub `prod` environment's token, the deploy key and `tools/setup-github.sh` are gone, and the server's two new keys, `GITHUB_RELEASES_TOKEN` and the optional `DEPLOY_ALERT_WEBHOOK`, are in `prod`. The production database is the named volume `db_data`. `tools/rename-project.sh` renames the systemd units with the project. docs/accounts.md has every account and key in one place. Porting: everything under `deploy/`, `.github/workflows/deploy.yml`, `docker-compose.prod.yml`, and jq in `docker/php/Dockerfile`.
- **One server for the app and a site, behind a front Caddy** (docs/edge.md). `deploy/edge/` is the server's front Caddy: it owns ports 80 and 443, gets and renews every hostname's certificate, redirects HTTP to HTTPS, and forwards each hostname to its project's Caddy over the `edge` Docker network. The app's Caddy serves plain HTTP, publishes only the loopback cron port, and trusts the visitor's address the front Caddy forwards, which reaches PHP as `REMOTE_ADDR`. A deploy refuses to start without the front Caddy.
- **Caddy is pinned to 2.11.9**, an exact patch instead of the floating `caddy:2.11`, which builds from whatever older image a machine has cached: 2.11.8 and 2.11.9 fix the advisories published on 2026-11-04. `CaddyfileTest` holds the pin. Porting: the `image:` line in `docker-compose.yml`.
- **Production runs on Debian 13**, not Ubuntu LTS (docs/fresh-install.md, README.md). Nothing in deploy/ is distribution-specific.
- **The Compose project is named for the slug** (`name:` in `docker-compose.yml`), so containers and volumes are the project's wherever it is cloned, not the folder's. Porting: add `name: <your slug>` at the top of `docker-compose.yml`; on a server the folder is already `/opt/<slug>`, so volume names do not change.

## [0.2.0] - 2026-10-19

### Added
- **Waffle Iron modules** (docs/modules.md): a feature written down so an AI agent can build it into any Waffle app. A module needs a `MODULE.md` (the feature in depth, its roles and permissions, its migrations) and a `MODULE-TEST.md` (desired outcomes and how to test them); reference code and tests are optional. It can be a directory, a `.zip` or a single `.module.md` prompt file. Modules live in their own repositories and are listed in [Waffle Iron](https://github.com/treehousetim/waffle-iron). Drop one into `modules/` and `ModulesTest` checks it against the format, including that every failure is covered by an outcome, that it holds no symlinks or non-ASCII file names, and that a directory module hashes the same everywhere (the hash rule is in the spec); a fixture module keeps the checks running when `modules/` is empty.
- **The first module, [short links](https://github.com/treehousetim/waffle-short-links)** (its own repository, listed in Waffle Iron): `yoursite.com/go/<code>` redirects with daily click counts and nothing tracked about who clicks; pause, expiry, safe generated codes, and refusal of open-redirect targets. Specified, not yet proven on a Waffle version.

- **The module command, `./tools/module.sh`** (docs/module-command.md): `search`, `info`, `use` (or `install`), `record`, `outdated`, `upgrade`, `verify` and `doctor` for modules from Waffle Iron. `use` clones the catalogue (a fixed URL, refusing a rewritten history), picks the newest reviewed, unyanked version for this app's Waffle version, fetches the pinned commit only if it is on the source repository's own branches or tags, exports it with `git archive`, refuses symlinks, odd file names, control and invisible Unicode characters and a hash that does not match, runs the format check, shows what the module adds (flagging unapproved libraries and every HTML comment), asks, stages it under `.waffle/` and starts `claude` with a fixed prompt. `record` re-checks the staged copy and shipped tests, runs `./tools/test.sh --coverage` itself, and only then writes `modules.json`. The checks are PHP in `tools/module/`, held to 100% coverage; the format rules moved there from ModulesTest so both use the same ones. `setup.sh` ends by printing how to install Waffle Iron's `iron` launcher when it is missing.

- **Setups** (docs/setups.md): the ways to build with Waffle and Waffle Site, each with what it needs and what is built today: app; app + site on one server or two; back office + site; a static site published by GitHub release (DigitalOcean App Platform out of the box); one app with several sites; API only. Public pages rendered on each request are recorded as deliberately unsupported.
- **The content model, decided, not built** (docs/content-model.md; to ship in the skeleton, as the backend every derived project starts with): the tables behind anything a site publishes: publishable columns and a publish state machine, slug history, terms for hub pages, media described on upload, form submissions, sites; and the site API they serve.
- **Change notices** (AGENTS.md §4): when records a site publishes change, the app sends the record type and slugs from a queued job, and the site rebuilds only the pages affected; never "rebuild everything".
- **Decisions for v1** (RESOLVED_QUESTIONS.md): v1 after a real project; the content model as a Waffle Iron module, with blocks for pages, Markdown for posts, revisions per publish and object storage; matching majors with Waffle Site; joining by invitation, or by OAuth for open apps; projects own their code, with the changelog as the porting guide.
- **The queue** (docs/queue.md): `QueuePort` kept in MariaDB, so a job is enqueued in the same transaction as the change it describes; jobs claimed with `SKIP LOCKED` by a new `worker` Compose service (`src/cli/worker.php`, PHP now built with `pcntl`), coalesced by unique key, retried with exponential backoff and jitter, and marked dead after their last attempt, each attempt recorded in `job_runs`. A Queue page and `/api/queue` (new permission `queue-manage`, owners and administrators) list failed jobs to retry or discard; `/cron/queue` prunes finished jobs and answers 503 when the worker has stalled, which stops the heartbeat. Deploys stop the worker before migrations and start it after php restarts. Porting: add the `worker` service, the `pcntl` extension and the crontab line; run the migration.

### Changed
- **The test suite has run.** Its first full run was green apart from 72 warnings from tests that silenced file errors with `@`, which now check first; `--coverage` is at 100%. Coverage now also instruments `tools/` (pcov watches the whole repository except `vendor/`).
- **The database port.** Production no longer publishes MariaDB at all: the app, the tests and the nightly backup all reach it inside Docker. Locally it moves from 3308 to 11020 (still loopback only, `DB_HOST_PORT` to override), out of the way of other MySQL/MariaDB servers and other projects' stacks.

## [0.1.0] - 2026-10-13

### Changed
- **The backronym:** Waffle now stands for **W**eb **A**pplication **F**oundation **F**or **L**ay **E**ngineers.

### Added
- **`tools/setup.sh`, a guided first-time setup**: checks the machine and says how to install what is missing, asks for the slug, display name and hostname (suggesting each), renames, refreshes both lock files without starting the project, offers the first commit, and prints what is next. Every answer is also a flag, and it is safe to re-run. Runs on macOS (stock bash 3.2), Linux and WSL2; refuses native Windows shells with a pointer to WSL2.
- **`tools/setup-github.sh`** does the GitHub half of a first deploy in one command: creates the `prod` environment deployable from `v*` tags only, refuses a `prod-deploy` config holding anything but deploy credentials, and pipes a new read-only Doppler token straight into the environment's `DOPPLER_TOKEN`, never printed or on a command line. Safe to re-run; `--rotate-token` replaces the token.
- **Versioning and `tools/release.sh`.** `VERSION` is the one place a version is written: semver for the framework (Packagist reads the tags), one number per release for an app (`v1`, `v2`; `0` is never released). `release.sh` checks everything first (on `main`, clean, level with `origin`, tag free, `[Unreleased]` has notes, `gh` signed in), then bumps, moves the changelog section, runs the coverage gate (red puts it all back), commits, tags, pushes atomically and publishes the GitHub release. A new project starts its own stream: `VERSION` 0 and a fresh changelog recording the framework version it came from. The deploy workflow accepts only `vN` and is skipped in the framework's own repository, which would otherwise try to deploy its own releases (docs/releasing.md, with its failure list).
- **AGENTS.md: "First session in a new project"** tells an agent to name the project with `setup.sh` (never by hand), interview the user for §1, and write the first feature's failure list before any code; and never to handle secret values.
- **`composer create-project treehousetim/waffle <dir>`** runs that setup (docs/create-project.md, with its failure list).
- **MIT licence**, and a Packagist description and keywords.
- **README: services to sign up for, and a documentation table** that replaces `docs/README.md` as the one index.

### Changed
- **Caddy replaces nginx** as the web server, from one file (`docker/caddy/Caddyfile`) for local and production. It gets and renews the Let's Encrypt certificate itself: no certbot, no renewal hook, no certificate path in a config file. The hostname lives once, in `docker-compose.prod.yml`'s `SITE_ADDRESS`. Every nginx rule carries over (security headers on every response, deferred; asset caching; dotfiles refused; 2 MB bodies) and `CaddyfileTest` replaces `NginxHeadersTest` (docs/https.md, with its failure list).
- **Launch hand-holding in `deploy.sh`:** a DNS check before anything starts (`deploy/check-dns.sh`, against a public resolver; refuses the first deploy, warns afterwards, `SKIP_DNS_CHECK=1` for proxies), `caddy validate` before anything restarts, a graceful Caddy reload, and a wait for HTTPS with a valid certificate that says where to look if it does not come up.
- **Doppler is for production only, with two configs named for who reads them:** `prod-serve` (was `prd`; the server) and `prod-deploy` (GitHub Actions). The `dev` config and `doppler.yaml` are gone: local development has no secrets, every value defaults in `docker-compose.yml`, and First run is a plain `docker compose up -d`. AGENTS.md §8 says how to bring `dev` back when a feature first needs a local key, and never to point `doppler.yaml` at a production config.
- **Cron moved to its own port.** `/cron` is served only on 8081, published on the server's loopback address alone; the public site answers it with 404. Port 80 is public, and Docker's userland proxy can make an outside connection look like it came from the bridge network the old allow list trusted. The crontab now calls `http://127.0.0.1:8081/cron/<job>`.
- **`tools/rename-project.sh` renames Waffle's own names** (`waffle`, `Waffle`, `waffle.example.com`), gives `composer.json` the project's own name, keeps lines pointing at `treehousetim/waffle`, and validates the display name and hostname before touching anything.
- **`tools/changed-groups.sh`** maps `tools/`, `deploy/`, `docker/`, the Compose files, `composer.json` and `CHANGELOG.md` to `core`, whose tests assert them.

### Security
- **Composer is defended the same way** (docs/supply-chain.md). `tools/composer.sh` is the only way Composer runs, in the php service's container with no home directory; after `require`/`update`/`remove` it refuses a lock holding anything younger than a week (`composer.lock` records release times) and puts the files back. `COMPOSER_COOLDOWN_DAYS=0` lets an urgent fix in and records it in `cooldown-exceptions.txt`. The suite fails on a young package nobody recorded, so Composer run any other way is caught before a release. `allow-plugins` lists exactly the locked plugins (the stale `php-http/discovery` permission is gone). CI builds production `vendor/` with `--no-plugins --no-scripts` and runs `composer audit` before shipping. The lock was brought inside the window: `webmozart/assert` 2.5.0→2.4.1.
- **npm is defended against hijacked releases** (docs/supply-chain.md, with its failure list). `tools/npm.sh` is the only way npm runs: in a throwaway `node:26-alpine` container with only the repository mounted (no home directory, so no keys or tokens to steal), as your user, `node_modules` in a Docker volume; install scripts off there and in `src/frontend/.npmrc`; and `--before=<7 days ago>` on anything that picks versions (`NPM_COOLDOWN_DAYS=0` for an urgent fix, loudly). CI adds `npm audit signatures` between `npm ci` and the build. The lockfile was brought inside the window: `vite` 8.3.4→8.3.2, `vue-router` 5.4.0→5.3.1, `@vitejs/plugin-vue` 6.0.10→6.0.9 and 22 transitive packages had been published in the past week. Node is no longer needed on the host, and `setup.sh` no longer runs npm at all.
- **The form-body refusal decodes the path first.** `POST /%61pi/auth/login` with a form body reached the login route, because the router decodes the path and the check did not.
- **Sign-in refuses every account status but normal.** It checked only Delight's `isSuspended()`, so a banned, locked, archived or pending account got one successful sign-in before `AuthMiddleware` ended it.
